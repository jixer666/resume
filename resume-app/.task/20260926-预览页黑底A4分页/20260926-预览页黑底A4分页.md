## 2. 已确认决策

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 分页方式 | **真实分页**（按 A4 高度硬裁切，内容跨页续接，允许切断半行文字） | 与超级简历一致；实现为同一份内容按页做裁剪偏移，不丢数据 |
| 底部按钮 | **导出 / 样式 / 模块 / 更换模板** | 对齐现有能力：样式=全局样式面板，模块=模块设置；本轮「返回编辑」被替换为「更换模板」，导出由 P5 提前落地 |
| 「更换模板」语义 | **只换版式与样式，保留已填内容** | 换模板不动 `data`、不动模块顺序、不动模块显隐；只把新模板的 `LAYOUT` + `GLOBAL_STYLE` + 模块皮肤（`cptName`/`cptTitle`/`style`）/`layout` 栏位套到当前简历 |
| 导出格式 | **PDF** | 简历打印/投递的通用格式，微信小程序可 `uni.openDocument` 直接预览 |
| PDF 生成路线 | **无头浏览器打开 H5 预览页** | 小程序预览页已用 `ResumeRender` 渲染出最终效果，直接让后端浏览器打开它出 PDF，渲染代码零重写；若后端自产 HTML，需重做近两百套物料皮肤（Vue SFC + scoped SCSS + `v-bind('modelStyle.xxx')`），Java 侧无法复用 |
| PDF 引擎 | **Playwright Java（自带 Chromium）** | 用户明确选定；跨平台一致、字体可控、无需本机装 Chrome |
| 导出接口形态 | **同步返回文件流** | `GET /resume/export/{id}` 直接返回 `application/pdf` 二进制流；无状态、无任务表、无文件清理；与前端 `api/resume.ts` 已有的 `exportResumePdf(id)` 完全一致，前端零改动 |
| H5 导出页如何被访问 | **本地 dev server + 可配 URL** | 新增 `src/pages/export/index.vue`；开发时 `pnpm dev:h5` 跑在 9001；后端配 `resume.export.preview-url`，Playwright 拼 `?id=xxx&token=xxx` 打开 |
| H5 导出页数据来源 | **URL 带 token，页面自取详情** | 后端把当前请求的 JWT 拼进 URL；导出页用该 token 调已有的 `GET /resume/detail/{id}`，零新增接口 |

## 3. 技术方案

### 3.1 核心思路：一份内容、多页裁剪

不复制数据、不新写渲染器，避免破坏 `ResumeRender` 只吃 `props.json`、不读 store 的设计（P5 H5 导出页同源）。

```
外层 scroll-view（黑底）
  └─ 每页一个 .paper（794 × 1123，overflow: hidden）
        └─ 内层 .paper__inner（margin-top: -(pageIndex * 1123)px）
              └─ ResumeRender（同一份 json，渲染第 1..N 次）
```

- 先量出**未缩放**内容总高 `contentHeight`（`uni.createSelectorQuery().boundingClientRect()`，除以 `paperScale` 还原）
- `pageCount = max(1, ceil(contentHeight / PAPER_HEIGHT))`
- 第 i 页（0 基）内部整体上移 `i * PAPER_HEIGHT`，超出部分被 `overflow: hidden` 裁掉 → 形成真实分页效果
- 缩放：沿用现有 `paperScale`（`(windowWidth - 24) / 794`），每页外层占位高度 = `PAPER_HEIGHT * paperScale + 页间距`

### 3.2 mp 端限制与对策

| 限制 | 对策 |
| --- | --- |
| 无 `ResizeObserver` / DOM 测量 | 只用 `uni.createSelectorQuery().boundingClientRect()`，`onShow` 后 `nextTick + setTimeout(60)` 量一次 |
| wxss 不支持标签选择器 | 全部样式用 class 选择器，单位统一 px |
| 组件单根节点约束 | 预览页模板保持单根 `.page` |
| `@import` 相对路径 | 预览页在 `src/pages/edit/`，引 `style/` 用 `../../style/...`；弹层组件自身已 `@import`，无需重复 |
| `@keyframes` 会被 scoped 改名 | 预览页若需动画，写在独立非 scoped `<style>` 块 |
| `<image>` 默认 320×240 | 图标用 `MpIcon`（背景图方案），显式给宽高 |

### 3.3 数据一致性

- 预览页数据源仍是 `store.current`；`onShow` 时重新量高，从编辑页改完返回预览可自动重排页数
- 底部「样式」「模块」弹层直接复用 `GlobalStyleSheet` / `ModuleSettingSheet`，改动实时反映到 `store.current`，预览页 `computed` 自动刷新

### 3.4 R6：模块管理抽取共用组件

**问题**：预览页当前的模块管理弹层是简化版（只有列表 + 点击进设置），编辑页版本才有「上移/下移/显隐/删除 + 新增模块」四组操作，两处不一致。

**方案**：把编辑页的完整实现原样抽到 `src/components/ModuleManagerSheet.vue`，两页都改用该组件。

```
ModuleManagerSheet.vue
  props:  visible: boolean
  emit:   close
  内部自持：allModels / addableModels / moduleTitle
  内部调用 store：toggleModule / moveModule / removeModule / addModule
  打开模块设置：内部维护 showModuleSetting + settingKeyId，
               内嵌 <ModuleSettingSheet :visible :key-id @close />
```

- props 只有 `visible`，两页传 `showModuleSheet`；`@close` 里两页各自做「落库 + 重排分页」或「autoSave」
- 组件根 `<view v-if="visible" class="mask" @click="close">` → `.sheet--tall`，`@click.stop`
- 样式全部搬编辑页 L720-806（`.module-row` / `.module-main` / `.module-name` / `.module-state` / `.module-acts` / `.icon-btn` / `.add-grid` / `.add-chip` / `.module-empty`），并 `@import '../style/editor-sheet.scss'`
- 编辑页删掉弹层模板与相关样式、`allModels`/`addableModels` 两个 computed，改为挂组件（`toggleModule`/`moveModule`/`removeModule`/`addModule` 若页内无其他调用点一并删除，改由组件内部调 store）
- 预览页删掉简化版弹层模板与样式，改为挂同一组件

### 3.5 R7：更换模板（保留已填内容）

**store 新增方法** `applyTemplate(code: string)`，参照 `createResume` 与 `changeVariant` 的写法：

```
对 current 的每个模块 item：
  1. item.layout   = layoutOf(item.model, template)     // 新模板栏位
  2. item.cptName  = template.variants?.[model] || 原值  // 新模板皮肤
  3. item.cptTitle = 该皮肤对应的 cptTitle
  4. item.style    = clone(该皮肤的 style)
  5. applyGlobalStyleToItem(item, 新 GLOBAL_STYLE, 全部 key)
  6. item.data / item.show / 模块顺序 —— 完全不动
再：
  json.LAYOUT       = template.layout
  json.GLOBAL_STYLE = { ...原 GLOBAL_STYLE, ...template.style }
```

**预览页「更换模板」弹层**：复用首页的模板卡片网格范式（`resume-cover` + `templateTheme` / `templateSideColor` / `coverBackdrop`），选中即 `store.applyTemplate(code)` → 关闭 → 重新量高分页 → `store.saveCurrent()`。

### 3.6 R8：导出 PDF（后端 Playwright 打开 H5 预览页）

**链路**

```
preview.vue 点「导出」
  → GET /resume/export/{id}                （带 Authorization: Bearer <token>）
  → 后端：鉴权 → 取当前请求 token → Playwright 打开 H5 导出预览页
          http://127.0.0.1:9001/#/pages/export/index?id=xxx&token=xxx
  → H5 页：把 token 灌进 store → GET /resume/detail/{id} 自取详情 → ResumeRender 渲染
  → 后端：page.pdf({ format:'A4', printBackground:true, margin:0 })
  → 返回 application/pdf 二进制流
  → 小程序：uni.downloadFile → uni.openDocument({ fileType:'pdf', showMenu:true })
```

**为什么不让后端自产 HTML**：简历物料有近两百套皮肤（`cptName` 变体），全部是 Vue SFC + scoped SCSS + `v-bind('modelStyle.xxx')` 动态样式，`CompatRenderer.vue` 负责映射。Java 侧重写这套渲染的成本与长期维护代价都不可接受，所以改为「浏览器去跑前端已有的预览页」，所见即所得。

**后端要点**

- 依赖：`resume-platform/pom.xml` 加 `com.microsoft.playwright:playwright:1.40.0`（支持 Java 8）；首次运行自动下载 Chromium（CDN 已验证可达）
- 接口：`UserResumeController` 加 `GET /resume/export/{id}`，返回 `ResponseEntity<byte[]>`，`Content-Type: application/pdf`；`BaseService.download()` 的 contentType 固定为 `APPLICATION_OCTET_STREAM`，导出接口需自行构造 headers
- 服务：`UserResumeService` 加 `exportPdf(Long id)`；实现里 `validAndGetResume(id, SecurityUtils.getUserId())` 复用现成鉴权，再用 `tokenService.getToken(ServletUtils.getRequest())` 取当前请求 token 传给渲染器
- 渲染：`ResumePdfRenderer`（`com.abc.resume.resume.service.pdf`）懒启动 Chromium，`synchronized` 串行化；每次导出新开 `BrowserContext`（隔离登录态与缓存），viewport 794×1123，`waitForSelector('.rs-page')` + `waitForLoadState(NETWORKIDLE)` 后 `page.pdf()`；`@PreDestroy` 关闭浏览器
- 配置：`application-dev.properties` 加 `resume.export.preview-url=http://127.0.0.1:9001/#/pages/export/index`（`ResumePdfRenderer` 用带默认值的 `@Value`，未配置也能跑）
- H5 导出页：`src/pages/export/index.vue`，`navigationStyle: 'custom'`（全局蓝底导航栏会被印进 PDF）；根容器 794px 宽、`#fff` 背景；`onLoad` 里 `tokenStore.setTokenInfo({ token, expiresIn: 3600 })` → `resumeStore.loadResume(id)` → `<ResumeRender :json="resume" />`
- 小程序侧：`interceptor.ts` **未**注册 `downloadFile` 拦截器，`api/resume.ts` 自行拼 `getEnvBaseUrl()` + `Authorization: Bearer <token>`；下载域名需在 mp 后台配置白名单

**运行前置条件**

- 导出前 H5 预览页必须已启动（开发时 `pnpm dev:h5`，端口 9001），否则 Playwright 打不开页面
- Playwright 首次运行需联网下载 Chromium（约 150MB）
